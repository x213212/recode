# i18n architecture

RECODE currently stores `settings.language` as `"zh" | "en"`, but that value only chooses `statementZh` or `statementEn`. The UI, metadata, dates, categories, explanations, and domain labels are still Traditional Chinese.

## Target model

Keep interface language and problem-content language independent:

```ts
type UiLocale = "zh-TW" | "en";
type ContentLocale = "zh-TW" | "en";
```

Add `settings.uiLocale` without removing the existing `settings.language` until stored state has migrated safely. Locale dictionaries should be typed and contain only UI messages; date, number, relative-time, and plural formatting should use the active UI locale.

The first UI-i18n phase should:

1. Add typed `zh-TW` and `en` message dictionaries with identical keys.
2. Add `uiLocale` normalization and persistence without incrementing the current state version.
3. Update `document.documentElement.lang` when the UI locale changes.
4. Convert visible UI components one boundary at a time.
5. Keep a clear fallback marker when a translated problem body is unavailable.

## Stable data identifiers

Do not translate the current `category` string in place. It is used as both display text and a persisted logic key. Introduce stable `categoryId` and `sourceId` values first, then localize their labels.

A future problem schema should use maps rather than adding one field per language:

```ts
interface LocalizedProblemContent {
  title: string;
  statement: string;
  explanation: StructuredExplanation;
}

interface ProblemDetailV3 {
  categoryId: string;
  sourceIds: string[];
  content: Partial<Record<ContentLocale, LocalizedProblemContent>>;
}
```

`solution.py` and executable tests remain language-neutral. Test labels should be derived from a stable kind and ordinal instead of persisted translated text.

## Known data gap

All 481 current files have non-empty `statementEn`, but 37 contain only an English title and no English body. A future audit must reject title-only translations and use an explicit Traditional Chinese fallback until those entries are completed.

## Required tests

- dictionary key parity and interpolation
- invalid/missing locale normalization
- UI locale and statement locale persistence as separate settings
- `<html lang>` and locale-aware date/number formatting
- stable category/source IDs across languages
- localized-content fallback behavior
- a data audit that rejects title-only English statements
